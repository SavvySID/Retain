Getting started

Retain predicts the IBM Telco dataset's churn label and makes the fitted model inspectable. The site runs on your local computer; no paid API is needed.

  1. Open the overview. The top cards report full-source statistics and a held-out model result. The tenure chart uses actual held-out customers, grouped by months of tenure rather than dates.
  2. Filter the chart. Contract buttons compare cohorts. Hover or focus a group for its count and rates, or expand the accessible data table. Empty groups have no plotted rate.
  3. Inspect a customer. Search or filter the held-out queue, then choose Inspect. The source outcome is separate from the model prediction.
  4. Try a scenario. Change profile values and choose Predict & explain. Edited inputs have no observed outcome.

Reading a SHAP explanation

The prediction panel shows churn probability and the classification threshold selected using validation data. Positive SHAP contributions raise the model output; negative contributions lower it. The explanation includes input values, a baseline and a numeric reconstruction.

Check the units.For log-odds explanations, baseline plus contributions equals the raw model output. The sigmoid function converts this to probability. A contribution of 0.2 log-odds is not a 20-percentage-point effect.

SHAP describes fitted-model associations relative to its background data. It cannot establish that a feature caused departure or that changing it will retain a customer. Discussion prompts are rules, not measured interventions.

Batch scoring

  1. Download the actual held-out sample CSV.
  2. Keep the exact predictor headers and supported categories. Customer ID is optional. Do not include the target or excluded demographics.
  3. Upload a UTF-8, comma-separated file within the displayed size and row limits.
  4. The server validates every row before scoring. Invalid files receive errors; rows are not silently dropped.
  5. Download model probabilities, predicted classes and risk groups.

Uploads remain in memory and are not saved or sent to external services. Exported predictions are not verified future outcomes.

Evaluation method

A deterministic stratified split separates fitting, selection and final evaluation. Preprocessing is fitted on training rows only.

  • Training: fit preprocessing and candidate classifiers, including a dummy baseline.
  • Validation: choose the model by unrounded average precision and select its classification threshold.
  • Held-out test: report final metrics and curves without tuning on test labels.

The selected training-fitted model is retained after threshold selection. Model lab shows actual accuracy, precision, recall, F1, ROC AUC, average precision and Brier score, confusion counts, plots and provenance.

Small differences do not prove superiority.A tiny validation-score gap determines this run's selection, but does not establish that one algorithm is generally better.

Source data

The source is IBM's original Telco Customer Churn sample for a fictional company. Its label records departures in the source's last-month period, not a prospective forecast for a new population.

The pipeline records a source SHA-256, cleaning decisions and split membership. Customer ID, target, gender and the senior-citizen indicator are excluded from predictors. This does not prove fairness.

Blank total charges become zero only when the original row supports a zero-tenure customer. Other unexplained invalid or missing values are rejected.

Limitations to explain in a viva

  • A fictional-company benchmark does not establish production performance.
  • Random stratified holdouts do not replace temporal or external validation.
  • SHAP is a model explanation, not causal evidence.
  • Removing demographic predictors does not establish fairness; proxies and group disparities may remain.
  • Retention prompts have no measured uplift, savings or financial benefit.
  • New customer populations need fresh validation and may require schema changes and retraining.
  • This local single-analyst project does not include production authentication, hosting or multi-user governance.
