A FEW USEFUL ANSWERS

Understand the limits.
Then explore with confidence.

The guide covers the workflow and the reasoning in more detail.

Read the project guide ↗
What data am I looking at?

IBM's original Telco Customer Churn sample for a fictional company. The preview and customer queue use actual held-out rows from that source. They are not invented customer profiles or current operational telecom data.

Does a high score mean a customer will leave?

No. It is a model probability for the source's churn label, with uncertainty and errors. Performance on this benchmark does not establish accuracy for a new customer population.

What does a SHAP explanation tell me?

It shows how input features contribute to the fitted model's output relative to a background baseline. It describes associations, not causal reasons for departure or proof that an intervention will work.

Can I score my own customer file?

Yes, if it follows the shared input schema and upload limits. Start with the downloadable sample CSV. A new telecom population needs fresh validation before its predictions guide real decisions.

Where does my uploaded data go?

Files are validated and scored in local server memory. Uploads are not saved or sent to third-party services. You choose where to save the exported results.

How do I run or explain this project?

Use the README for local setup and the project guide for the workflow. The model card, methodology, data card and viva guide document the implementation, evidence and limitations.
